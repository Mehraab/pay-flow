# PayFlow API Catalog

Generated by scanning `payflow-api-gateway` (the single entry point, port 8080) and the
downstream services it proxies to. Only endpoints actually reachable through
`http://localhost:8080` are listed as gateway routes; internal-only endpoints
(`/internal/**`) and endpoints that exist on a downstream service but are **not**
currently wired into the gateway are called out explicitly in each section so the
frontend team doesn't assume they're reachable.

## Conventions

- **Monetary amounts** are always minor units (cents) as a JSON integer/long — e.g.
  `21400` for $214.00 — never `BigDecimal`/string. Field name is always `amountMinor`.
  Currency is a separate `currency` field, one of the `Currency` enum values: `USD`,
  `EUR`, `GBP`.
- **IDs** are UUIDs (string form over the wire).
- **Auth**: every route except `/auth/**` and `/actuator/**` requires `Authorization: Bearer
  <accessToken>`. The gateway's `JwtAuthenticationFilter` additionally requires the
  token's `role` claim to be `ROLE_OPERATOR` for any `/operator/**` path (403
  `Forbidden: Requires ROLE_OPERATOR` otherwise); a missing/invalid token on any
  protected path returns 401. There is no per-route merchant-vs-operator split outside
  of the `/operator/**` prefix — any authenticated role (`ROLE_MERCHANT` or
  `ROLE_OPERATOR`) can call the non-operator routes.
- **Merchant scoping**: when the caller's token has `role=ROLE_MERCHANT`, the gateway
  injects an `X-Merchant-Id` header (from the token's `merchantId` claim) onto the
  request forwarded downstream. Today no downstream controller actually reads that
  header to scope/filter a response — see the gap notes in Section 2.
- **Test card simulation** (`payflow-provider-gateway-service`'s `MockProviderGateway`):
  the mock processor routes purely on the `cardNumber`'s last 4 digits —
  `4242` → `APPROVED`, `0002` → `DECLINED` ("Insufficient funds"), `0069` → `DECLINED`
  ("Expired card"), `0119` → simulated processor timeout (throws after a 5s delay,
  surfaces as HTTP 500), anything else → `DECLINED` ("Generic decline"). This drives
  the Temporal saga into its compensation path.
- **Forced ledger failure**: `POST /api/v1/payments` accepts either a
  `X-Force-Ledger-Failure: true` header or `"forceLedgerFailure": true` in the body.
  Either forces the ledger-posting step to throw, which drives the saga to compensate
  the payment to `REFUNDED`. This flag is gateway→command-service only; the header is
  also accepted directly by the ledger service's internal `/internal/ledger/post-capture`.
- CORS: no CORS configuration exists anywhere in `payflow-api-gateway` — no
  `WebMvcConfigurer`/`@CrossOrigin` found. A browser-based frontend calling
  `localhost:8080` from a different origin will currently be blocked by the browser
  unless CORS is added.

## Section 1: Auth APIs (`/auth/*`)

Handled directly by the gateway (`AuthController`); not proxied anywhere. These are the
only paths the JWT filter leaves public (`shouldNotFilter` matches `/auth/**` and
`/actuator/**`).

### `POST /auth/token`
- **Target service**: `payflow-api-gateway` (local, not proxied)
- **Roles allowed**: Public
- **Request body** (`TokenRequest`):
  ```json
  { "role": "MERCHANT | OPERATOR", "merchantId": "uuid, optional" }
  ```
  - `role` must be exactly `"MERCHANT"` or `"OPERATOR"` (without the `ROLE_` prefix) or
    the gateway returns `400 { "error": "role must be MERCHANT or OPERATOR" }`.
  - `merchantId` is only meaningful for `role: "MERCHANT"`. If omitted, the gateway
    generates a random one. Ignored for `role: "OPERATOR"`.
- **Response body** (`TokenResponse`, 200):
  ```json
  { "accessToken": "string", "refreshToken": "string", "tokenType": "Bearer", "expiresIn": 900 }
  ```
  - `expiresIn` is seconds (access-token TTL, configured at 900s / 15 min).
  - Access token carries claims `role` (`ROLE_MERCHANT`/`ROLE_OPERATOR`) and, for
    merchants, `merchantId`.

### `POST /auth/refresh`
- **Target service**: `payflow-api-gateway`
- **Roles allowed**: Public
- **Request body** (`RefreshTokenRequest`): `{ "refreshToken": "string" }`
- **Response**: `200` with a new `TokenResponse` (same shape as above), or `401
  { "error": "<message>" }` if the refresh token is invalid/expired/revoked.

### `POST /auth/revoke`
- **Target service**: `payflow-api-gateway`
- **Roles allowed**: Public (no bearer token required to revoke — only the refresh
  token itself is needed)
- **Request body** (`RefreshTokenRequest`): `{ "refreshToken": "string" }`
- **Response body**: `200 { "status": "REVOKED" }`

## Section 2: Payments APIs (`/api/v1/payments/*` — Command & Query)

### `POST /api/v1/payments`
- **Gateway route**: `PaymentGatewayController.createPayment` → proxies to
  `payflow-payment-command-service` `POST /payments`
- **Roles allowed**: `ROLE_MERCHANT` or `ROLE_OPERATOR` (any authenticated token;
  not gated to merchant-only)
- **Headers**:
  - `Idempotency-Key` (required at the command service — the gateway forwards it if
    present but does not itself enforce presence, so a missing key surfaces as
    whatever 4xx the command service returns)
  - `X-Force-Ledger-Failure: true` (optional, see Conventions above)
- **Request body** (`CreatePaymentRequest`):
  ```json
  {
    "merchantId": "uuid",
    "amountMinor": 21400,
    "currency": "USD",
    "cardNumber": "4242424242424242",
    "forceLedgerFailure": false
  }
  ```
- **Response body** (`CreatePaymentResponse`, 201): `{ "paymentId": "uuid" }`
  - Note: this is a CQRS command dispatch — the response only confirms the payment
    was accepted and assigned an ID. Actual capture/decline happens asynchronously via
    the Temporal saga; poll `GET /api/v1/payments/{id}` for status.
- **Gap**: `X-Merchant-Id` (injected for `ROLE_MERCHANT` callers) is not read by this
  endpoint — the `merchantId` in the body is authoritative and is not cross-checked
  against the caller's token, so a merchant token can currently submit a payment for
  any `merchantId`.

### `GET /api/v1/payments/{id}`
- **Gateway route**: `PaymentGatewayController.getPayment` → proxies to
  `payflow-payment-query-service` `GET /payments/{id}`
- **Roles allowed**: `ROLE_MERCHANT` or `ROLE_OPERATOR`
- **Path params**: `id` (UUID, the payment ID)
- **Response body** (`PaymentView`, 200) or `404` if not found:
  ```json
  {
    "paymentId": "uuid",
    "merchantId": "uuid",
    "amountMinor": 21400,
    "currency": "USD",
    "status": "string (e.g. PENDING, CAPTURED, DECLINED, REFUNDED)",
    "providerRef": "string | null",
    "declineReason": "string | null"
  }
  ```
- **Gap**: not scoped by `X-Merchant-Id` — any authenticated merchant can fetch any
  payment by ID, not just their own.

### `POST /api/v1/payments/{id}/refund`
- **Gateway route**: `PaymentGatewayController.refundPayment` → proxies to
  `payflow-payment-command-service` `POST /payments/{id}/refund`
- **Roles allowed**: `ROLE_MERCHANT` or `ROLE_OPERATOR`
- **Path params**: `id` (UUID)
- **Request body**: none
- **Response**: `200`, empty body (command dispatch, fire-and-forget)

### Not exposed through the gateway (command service, direct/internal only)
These exist on `payflow-payment-command-service` but have no corresponding gateway
route — reachable only by calling the service directly on its own port, or (for the
`/internal/*` ones) intended to be called only by the Temporal orchestrator:
- `POST /internal/payments/{id}/capture` — body `{ "providerRef": "string" }`
- `POST /internal/payments/{id}/fail` — body `{ "declineReason": "string" }`
- `POST /internal/payments/{id}/refund` — no body (internal variant of the public refund route)

## Section 3: Ledger & Payout APIs (`/accounts/*`, `/payouts/*`)

**Gap — none of these are currently routed through the gateway.** The gateway's
`PaymentGatewayController` only proxies `GET /operator/ledger/integrity` from
`payflow-ledger-service` (documented under Section 4, since it's an `/operator/**`
route). The endpoints below exist on `payflow-ledger-service` (port 8085 by default)
but are **not reachable via `localhost:8080`** today. Listed here per the output
contract, with target service/roles reflecting what the code would imply if a route
were added, since there's no gateway-level role gate to observe directly.

### `GET /accounts/{accountName}/balance`
- **Target service**: `payflow-ledger-service` (`LedgerController.platformAccountBalance`)
- **Not gateway-routed.** Looks up a platform account by name, falling back to a
  unique merchant account matched by name/slug.
- **Response body** (`AccountBalanceResponse`, 200) or 404:
  `{ "accountName": "string", "balanceMinor": 100000 }`

### `GET /accounts/{merchantId}/{accountName}/balance`
- **Target service**: `payflow-ledger-service` (`LedgerController.merchantAccountBalance`)
- **Not gateway-routed.**
- **Path params**: `merchantId` (UUID), `accountName` (string)
- **Response body**: same `AccountBalanceResponse` shape as above, or 404.

### `GET /ledger?transaction={transactionRef}`
- **Target service**: `payflow-ledger-service` (`LedgerController.entriesForTransaction`)
- **Not gateway-routed.**
- **Query params**: `transaction` (string, required)
- **Response body** (`LedgerEntryResponse[]`, 200):
  ```json
  [{
    "id": "uuid",
    "transactionRef": "string",
    "debitAccountId": "uuid",
    "creditAccountId": "uuid",
    "amountMinor": 21400,
    "postedAt": "2026-01-01T00:00:00Z"
  }]
  ```

### `POST /payouts`
- **Target service**: `payflow-ledger-service` (`PayoutController.createPayout`)
- **Not gateway-routed.**
- **Request body** (`CreatePayoutRequest`): `{ "merchantId": "uuid" }`
- **Response body** (`PayoutResponse`, 201):
  ```json
  {
    "id": "uuid",
    "merchantId": "uuid",
    "amountMinor": 21400,
    "currency": "string",
    "status": "string",
    "createdAt": "2026-01-01T00:00:00Z"
  }
  ```

### `GET /payouts/{id}`
- **Target service**: `payflow-ledger-service` (`PayoutController.getPayout`)
- **Not gateway-routed.**
- **Response body**: same `PayoutResponse` shape, or 404.

### `POST /payouts/sweep`
- **Target service**: `payflow-ledger-service` (`PayoutController.sweep`)
- **Not gateway-routed.** Triggers the EOD sweep across all eligible merchants —
  shaped like an operator/batch action, so if/when it's wired into the gateway it
  should likely sit under `/operator/**` rather than be left open.
- **Request body**: none
- **Response body** (`PayoutResponse[]`, 200): array of the shape above.

### Internal-only (ledger)
- `POST /internal/ledger/post-capture` — body `PostCaptureRequest { paymentId, merchantId,
  amountMinor, currency }`, response `PostCaptureResponse { status }`. Accepts the same
  `X-Force-Ledger-Failure` header described in Conventions. Called by the Temporal saga,
  not by any frontend-facing route.

## Section 4: Operator & Saga APIs (`/operator/*`)

All routes in this section require `ROLE_OPERATOR` — enforced centrally by the
gateway's `JwtAuthenticationFilter` for the whole `/operator/**` prefix (not
per-endpoint in the downstream services, which trust the gateway).

### `GET /operator/ledger/integrity`
- **Gateway route** → proxies to `payflow-ledger-service` `GET /operator/ledger/integrity`
- **Roles allowed**: `ROLE_OPERATOR`
- **Response body** (`LedgerIntegrityResponse`, 200):
  ```json
  { "totalDebitsMinor": 500000, "totalCreditsMinor": 500000, "balanced": true }
  ```

### `GET /operator/providers` and `GET /operator/providers/**`
- **Gateway route**: `PaymentGatewayController.proxyProviderRouting` (wildcard,
  methods GET/PATCH) → proxies to `payflow-provider-gateway-service`
  `ProviderRoutingController.listProviders`
- **Roles allowed**: `ROLE_OPERATOR`
- **Response body** (`ProviderConfig[]`, 200):
  ```json
  [{ "id": "string", "name": "string", "priority": 1, "active": true }]
  ```

### `PATCH /operator/providers/{id}/routing`
- **Gateway route**: same wildcard proxy as above → proxies to
  `payflow-provider-gateway-service` `ProviderRoutingController.updateRouting`
- **Roles allowed**: `ROLE_OPERATOR`
- **Path params**: `id` (provider id, string)
- **Request body** (`UpdateRoutingRequest`, partial update — either field may be
  omitted/null): `{ "priority": 2, "active": false }`
- **Response body**: updated `ProviderConfig` (200), or 404 if the provider id doesn't exist.

### `GET /operator/saga-events`
- **Gateway route**: `PaymentGatewayController.sagaEvents` → proxies to
  `payflow-payment-orchestrator` `SagaEventsController.sagaEvents`
- **Roles allowed**: `ROLE_OPERATOR`
- **Response body** (`SagaEventResponse[]`, 200), read from Temporal's own Visibility API:
  ```json
  [{
    "workflowId": "string",
    "status": "string",
    "startTime": "2026-01-01T00:00:00Z",
    "closeTime": "2026-01-01T00:00:05Z"
  }]
  ```

### `GET /operator/webhooks/dlq/**` and `POST /operator/webhooks/dlq/**`
- **Gateway route**: `PaymentGatewayController.proxyWebhookDlq` (wildcard) → proxies to
  `payflow-notification-service` (`@RequestMapping("/operator/webhooks/dlq")` on
  `WebhookDlqController`)
- **Roles allowed**: `ROLE_OPERATOR`

  #### `GET /operator/webhooks/dlq`
  - Lists dead-lettered webhook deliveries.
  - **Response body** (`WebhookDeliveryResponse[]`, 200):
    ```json
    [{
      "id": "uuid",
      "endpointId": "uuid",
      "eventType": "string",
      "status": "string",
      "attemptCount": 5,
      "responseCode": 500,
      "lastAttemptAt": "2026-01-01T00:00:00Z",
      "nextRetryAt": "2026-01-01T00:05:00Z"
    }]
    ```

  #### `POST /operator/webhooks/dlq/{id}/retry`
  - **Path params**: `id` (UUID, the delivery id)
  - **Request body**: none
  - **Response body**: updated `WebhookDeliveryResponse` (200), or 404 if the delivery
    doesn't exist.

### Internal-only (not operator-facing, not gateway-routed)
- `POST /internal/webhooks/dispatch` (`payflow-notification-service`) — body
  `DispatchWebhookRequest { merchantId, eventType, payload }`, response
  `DispatchWebhookResponse { status: "ENQUEUED" }`. Enqueues a webhook for delivery;
  called by domain event handlers, not by any frontend route.
- `POST /internal/providers/charge` and `POST /internal/providers/void`
  (`payflow-provider-gateway-service`) — called only by Temporal Activities
  (`authorizeAndCapture` / `reverseProviderCharge`), never by the gateway. Bodies:
  - `charge`: `AuthorizePaymentRequest { paymentId, amount: Money, cardNumber }` →
    `AuthorizePaymentResponse { status: APPROVED|DECLINED, providerRef, declineReason }`
  - `void`: `VoidChargeRequest { providerRef }` → `VoidChargeResponse { status, providerRef }`

## Summary: endpoints NOT reachable via the gateway today

For quick frontend-team reference — these exist in the codebase but calling
`localhost:8080` for them will 404 (no gateway route matches):
- `GET /accounts/{accountName}/balance`
- `GET /accounts/{merchantId}/{accountName}/balance`
- `GET /ledger?transaction=...`
- `POST /payouts`, `GET /payouts/{id}`, `POST /payouts/sweep`
- All `/internal/**` endpoints on every service (by design — orchestrator/Temporal-only)
